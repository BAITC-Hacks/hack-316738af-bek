# Frontend → біріктірушіге сұраулар

API 1.0.0 және contracts файлдары өзгертілмеді.

1. **Git қолжетімділігі шешілді.** `Aslanxz008` аккаунтымен жеке репозиторий ашылды. Frontend `main` тармағының `d442e9ff6274cbc4c2e1da04a7a8a46aef06c72d` commit-інен `team/frontend` тармағына дайындалды. Main ішінде ортақ contracts әлі жоқ; `team/ai-engine` ішіндегі келісімнің SHA-256 хэші frontend-пен бірдей. Біріктіруші AI тармағымен бірге contracts-ты main-ге енгізуі керек. Frontend бөтен рөлдің файлдарын қоспайды.
2. **Review түсініктемесін оқу.** `Finding` ішінде тек `review_status` бар. `FindingReview` тек PATCH жауабында келеді; жеке GET жоқ. Қазіргі UI шешімді сақтайды және нәтиже мәртебесін қайта оқиды, бірақ refresh-тен кейін ескі note-ты көрсете алмайды. Ол шектеу UI-да көрсетіледі, ескі note есептен оқылады. Қажет болса келесі ортақ келісімде review оқу мүмкіндігін қосу туралы шешім қабылдаңыз.
3. **Құжат метадерегі.** Рөлдік тапсырмада редакция/метадерек аталады, бірақ `DocumentPatch` тек `expected_revision` және `version` қабылдайды. Қазіргі frontend метадеректі көрсетеді, топты ғана өзгертеді. Title/edition өңдеу қажет болса тек орталық келісім жаңартылсын.
4. **Live қабылдау.** Backend frontend/dist жинағын ұсынуы, `/api` маршруттарын, original/export blob-тарын, credentials/session тексеруін және JSON Error схемасын қамтамасыз етуі керек. Frontend HTTP сценарийлері имитацияланған жауаптармен тексерілген; нақты парсер және engine бөлігімен бірлескен тест әлі қажет.
5. **Қорғалған deployment.** Егер `APP_ACCESS_TOKEN` қолданылса, браузерге серверлік cookie немесе сол origin-дегі қорғалған кіру арқылы сессия берілуі керек. Құпия токенді VITE айнымалысына енгізу қарастырылмаған. Бөлек dev origin болса credential-aware CORS керек.

Бұл сұраулар бар frontend-ті іске қосуға кедергі емес. Келісімнің өріс/маршрут атаулары өз бетінше кеңейтілмеді.

# Екінші қатысушының backend AI-ына арналған тапсырма

Сен HackAlem AI хакатонындағы Qurylym AI жобасының backend бөлігіне жауап бересің. Frontend және AI қозғалтқышын басқа қатысушылар жасайды. Сенің бөлігің ортақ келісім арқылы олармен бірігуі тиіс.

Алдымен `TZ_v2.md` немесе оның `docs/` көшірмесін, `TEAM_WORKFLOW.md`, `contracts/openapi.json` және `contracts/CONTRACT_SHA256.txt` оқы. Ортақ бастапқы commit-тен баста. Келісім нұсқасы 1.0.0. Репозиторий ашылмаған болса, оның орналасуын сұра; бөлек толық өнім құрма.

Өзгертуге рұқсат: `backend/**`, `Dockerfile`, `compose.yaml`, `.env.example`, `README.md`, `.gitignore`, `coordination/backend.md`, `coordination/requests/backend.md`. Frontend, AI engine және contracts файлдарын өзгертпе. Жаңа өріс/маршрут қажет болса, алдымен өз request файлыңа ұсыныс жаз.

Стек: Python, FastAPI, Pydantic, SQLite; DOCX үшін python-docx/OOXML, мәтіндік PDF үшін pypdf, XLSX үшін openpyxl. AI қозғалтқышы репозиторий түбіндегі `ai_engine` Python пакеті болады. `from ai_engine.pipeline import analyze` арқылы `await analyze(payload, emit_progress=callback)` шақырылады. Оның интерфейсі TEAM_WORKFLOW.md ішінде нақты берілген. Бөлек LLM pipeline жасама.

Міндеттер:

1. OpenAPI файлындағы барлық маршрутты, жауап кодын, required/nullable өрісін және Error схемасын дәл орында. Әр жаңа талдауға ID, әр өзгерген кіріс жиынына revision бер.
2. Before/after тобына бірнеше файл жүктеу; көлем/формат/бұзылуды тексеру. Түпнұсқа, SHA-256, тұрақты source ID, тармақ және контекст сақтау. Бір сұрау бір файл; жауап толық жаңарған AnalysisState.
3. DOCX ішіндегі мәтін, кесте, автоматты нөмір және бір абзацқа біріктірілген тармақтарды оқу. Тақырыпты/субъектіні байланыстыру. Мазмұн кестесі мен қайталанған header міндеттерді көбейтпейді. PDF беттерін, XLSX sheet/cell_range сақтау. Танылмаған графика, бос тармақ және парсинг қатесін диагностикаға енгізу; оларды үнсіз тастамау.
4. SQLite-те analysis, document, source, result және review нұсқаларын сақтау. Idempotency, бір active job және failed/partial күйін іске асыру. Ауыр жұмысты оқиғалар циклінен бөлу. Қайта іске қосылған сервер үзілген job-ты түсінікті күйге ауыстыруы тиіс.
5. AI-ға дәл AnalysisInput жіберу және келген AnalysisResult схемасын тексеру. API адаптерінің тестіне fake engine инъекциялауға болады; қалыпты runtime run маршруты fake қорытынды қайтармайды. AI модулі жоқ болса, түсінікті unavailable қатесі берілсін.
6. SourceEvidence және түпнұсқаны жүктеу, review сақталуы, HTML/CSV экспорты. Басқа analysis source ID қолжетімсіз; түпнұсқа үзінді дұрыс. CSV формула инъекциясынан қорғалады, HTML мәтін қауіпсіз escape етіледі. Есеп санақтары нәтижемен бірдей.
7. Frontend build-ін серверден ұсынатын Docker дайында. `backend/requirements.txt` пен `ai_engine/requirements.txt` екеуін біріктіріп орнат; AI тәуелділігіне қажет қайшылық болса біріктірушіге жаз. Frontend өз package/lock файлдарын басқарады.
8. Қазақша README-ді ұйымдастырушының 11 бөлімімен жүргіз: мүмкіндіктер, негізгі жол, технология/архитектура, нақты іске қосу командалары, бақылау, деректер, шектеулер және бар болса deployed URL. Орындалмаған мүмкіндікті немесе тестті өтті деп жазба.

Алғашқы кезеңде health, upload/parse, source және schema-valid state дайындап, AI адаптерін fake арқылы тексер. Соңғы міндетті тест: жүктеу → AI → нәтижені сақтау → source → review → export. DOCX/PDF/XLSX парсерлерінің шағын бақылау файлдарын және API ақау/нұсқа тесттерін өз `backend/tests/` ішіне жаз.

Дайындық есебінде: commit, өзгерген файлдар, іске қосқан командалар, нақты тест нәтижелері, AI/Frontend-тен қажет қалған интерфейстер және шектеулер. `.env.example` ішінде кілттердің тек бос үлгісі болуы керек. Ортақ main тармағына басқа қатысушылармен бір уақытта push жасама; өз тармағыңды біріктірушіге бер.

# Үшінші қатысушының frontend AI-ына арналған тапсырма

Сен HackAlem AI хакатонындағы Qurylym AI өнімінің frontend бөлігіне жауап бересің. Backend пен AI қозғалтқышын басқа қатысушылар жасайды. Мақсат — ұйымдастыру өзгерістерін салыстыру нәтижесін қызметкерге нақты дәлелдермен көрсету.

Алдымен `TZ_v2.md` немесе оның `docs/` көшірмесін, `TEAM_WORKFLOW.md`, `contracts/openapi.json`, `contracts/CONTRACT_SHA256.txt` және төрт `*.example.json` файлын оқы. Ортақ бастапқы commit-тен баста. API келісімі 1.0.0; маршрут пен өріс атауларын өзгертпе. Репозиторий ашылмаса, орналасуын сұра; бөлек дербес өнім жасама.

Өзгертуге рұқсат: `frontend/**`, `coordination/frontend.md`, `coordination/requests/frontend.md`. Backend, AI engine, contracts, түпкі Docker және README файлдарын өзгертпе. Қажет келісім өзгерісін request файлына жаз.

Стек: React, TypeScript, Vite, Tailwind CSS. Өз `frontend/package.json` және lock-файлыңды басқар. API клиентін бір модульге жина: әдепкі сол origin-дегі `/api`, бөлек dev қажет болса `VITE_API_BASE_URL`. OpenAI немесе NVIDIA-ға браузерден тікелей сұрау жіберме.

Үш негізгі көрініс жаса:

1. Құжат жүктеу: «Дейін» және «Кейін» аймақтары, бірнеше файл, құжаттың тобы/редакциясы, файл күйі мен диагностика, салыстыруды бастау. Файлдар API-ға кезекпен жіберіледі. Әр upload жаңарған AnalysisState қайтарады.
2. Нәтижелер: құрылым, функциялар және тәуекелдер қойындылары. Функциялар кестесінде before/after жауапты, мәтін, coverage және бірнеше өзгеріс белгісі көрінеді. Тәуекелдер түрі, жаңалығы, бөлімше және review күйі бойынша сүзіледі.
3. Дәлел және есеп: оң жақ панельде SourceEvidence арқылы нақты мәтін, құжат атауы, тармақ/PDF беті/XLSX ұяшығы, контекст және түпнұсқаны жүктеу. Қолдайтын/қарсы дәлел, ұсынылатын әрекет, confirmed/rejected/needs_information шешімі және түсініктеме. HTML/CSV экспортын API арқылы алу.

Негізгі UI қазақша, түпнұсқа орысша үзінді өзгермейді. Таза іскерлік дизайн, оқылатын кесте, қалыпты аралықтар, мәртебе түсімен бірге мәтін. Қамту мен санақ API-дан келеді; модель сапасы ретінде ойдан пайыз көрсетпе. Жоғалу жағдайында after_function_ids бос болатынын және барлық өрістің бірдей толмайтынын ескер.

API күйлері: uploaded/parsing/extracting/matching/verifying/completed/partial/failed. Progress polling жаса; нәтижені backend completed/partial дегенде ал. 409 нұсқа қайшылығында ағымдағы күйді жаңарт. Бір run әрекетінің желілік retry-ы бір Idempotency-Key қолданады. Қате, бос нәтиже, ішінара дерек, ұзақ өңдеу және бетті жаңарту жағдайлары жұмыс істесін.

Backend дайын болғанша төрт жасанды мысалды typed mock provider арқылы пайдалана аласың. Мұндай режимде «Жасанды demo деректері» белгісі міндетті. API қатесі кезінде қолданба mock-қа үнсіз ауыспайды. Соңғы біріктірілген нұсқада live режим әдепкі болады. Жасанды мысалдан күтілетін «нақты табылды» статистикасын жазба.

P0 толық болған соң ғана P1 ретінде екі бағанды құрылым картасы және функцияның before → after жолын қос. Ол дайын units/unit_changes/mappings деректерін пайдалансын. Жаңа чат, басқа өнім модулі, жаңа backend немесе жаңа API енгізбе.

Тексеру: TypeScript және production build, негізгі Playwright сценарийі, source ашылуы, review сақталуы, бос/partial/error күйлері. Маңызды артефакт — API-мен толық жүктеу → нәтиже → дәлел → шешім → экспорт жолы. Backend дайын емес тесттерді толық интеграция өтті деп жазба.

Дайындық есебінде: commit, өзгерген файлдар, нақты орындалған командалар мен нәтижелер, UI-да істейтін жолдар, mock/live күйі және backend-ке қажет қалған нәрселер. Өз тармағыңды біріктірушіге бер.

# Бірінші қатысушының AI қозғалтқышына арналған тапсырмасы

Сен HackAlem AI хакатонындағы Qurylym AI жобасының AI қозғалтқышына жауап бересің. Өнімнің мақсаты: бұрынғы/кейінгі ұйымдық құжаттарды салыстырып, бөлімшелер мен функциялардың өзгерісін, ықтимал жоғалу, қайталану және мүдделер қақтығысын нақты құжат үзінділерімен көрсету. Бұл ортақ үш бөлікті жобаның бір бөлігі.

Алдымен `TZ_v2.md` немесе репозиторийдегі оның `docs/` көшірмесін, `TEAM_WORKFLOW.md`, `contracts/openapi.json` және `contracts/CONTRACT_SHA256.txt` файлдарын оқы. Осы жоба үшін берілген ортақ commit-тен баста. API келісімі 1.0.0 және Python интерфейсі өзгермейді. Репозиторий ашылмаған болса, оның орналасуын сұра; басқа тәуелсіз өнім жасама.

Өзгертуге рұқсат: `ai_engine/**`, `evaluation/**`, `coordination/ai.md`, `coordination/requests/ai.md`. Backend, frontend, contracts, Docker және түпкі README файлдарын өз бетінше өзгертпе. Келісімде кедергі табылса, нақты ұсынысты request файлына жазып, одан тәуелсіз жұмысты жалғастыр.

Нақты интерфейс: `ai_engine/pipeline.py` ішінде `async def analyze(payload: dict, emit_progress=None) -> dict`. Кіріс — AnalysisInput, шығыс — AnalysisResult. Callback бар болса, `await emit_progress(event)`; event — ProgressEvent. `ai_engine/errors.py` ішінде `AnalysisError(code, message, retryable=False)` жаса. Backend парсер берген үзінділерді пайдалан; файл жүктеу, қайта парсинг және дерекқор серверін жасама.

Міндеттер:

1. Пайдаланушы берген үзінділерден Unit және Function шығару. Тақырыптағы субъект, тыйым, мерзім, ерекшелік және жауапкершілік аясын сақтау. Ойдан шығарылған source ID қабылдамау.
2. Екі нұсқадағы бөлімшелерді салыстыру. Ресми өкімдегі қайта ұйымдастыру мен функцияға негізделген болжамды ажырату; атау өзгеруі, бірігу және бөліну үшін бірнеше байланыс қолдану.
3. Бұрынғы әр функцияны кейінгі барлық бөлімшелерден іздеу. Ауысуды жоғалу деп белгілемеу. Толық/ішінара/табылмаған/белгісіз қамтуды және қатар өзгерістерді бөлек сақтау.
4. Екі нұсқада қайталану мен үйлеспейтін рөлдерді анықтап, тәуекелдің өзгерісін көрсету. Ортақ етістік, иерархиялық нақтылану және әртүрлі объект өздігінен қайталану болмайды.
5. Жоғалу үшін қосымша толық іздеу, жоғары әсері бар жағдай үшін қарсы дәлел және қорғаныс шараларын тексеру. Әр маңызды қорытындының нақты дәлелі мен қажетті контексті болуы тиіс.
6. Шығысты схемаға және семантикалық инварианттарға тексеру. Санақ кодпен есептеледі. Қысқаша қорытынды тек нәтижедегі finding/mapping-ке сүйенеді. Қызметкер күйі тек `unreviewed`.
7. OpenAI арқылы құрылымды талдау; NVIDIA қолжетімді болса кандидаттарға мағыналық іздеу. Құпия кілттер тек орта айнымалыларында. Модель/промпт нұсқасы, нақты usage, retry және timeout тіркеледі. Сервис қатесін жалған live нәтижемен алмастырма.
8. `evaluation/` ішінде алдын ала күтілетін нәтижелері бар бақылау жиынын және сапа есебін жасақта. Нақты №8/№9 үзінділеріндегі ауысу, бос тармақ және тыйым тексеріледі. Жасанды жауаптарды runtime модельге берме және бөлімше атауларына жауапты алдын ала байлама.

Алдымен schema-valid кіріс/шығыс пен бір толық салыстыру жолын іске қос. Содан кейін негізгі жоғалу, ауысу, қайталану және қақтығыс сценарийлерін толықтыр. Әр кезеңде нақты тексеру жаса. Келісім мысалдары — тек жасанды тест деректері. Нақты API қолжетімсіз болса, соны атап, API-сыз логика мен тесттерді аяқта.

Дайындық есебінде: commit, өзгерген файлдар, орындалған командалар, тест нәтижелері, live шақыру болды ма, анықталған шектеулер, backend-ке қажет env/dependencies. Пайдаланылған тәуелділіктердің нұсқаларын өз `ai_engine/requirements.txt` файлыңа бекіт. Уақыттың нақты дедлайнын сақта; жаңа қосымша өнім мүмкіндігін ойдан кеңейтпе.

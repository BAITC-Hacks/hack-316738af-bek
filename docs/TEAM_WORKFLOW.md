# Үш қатысушы және олардың AI құралдары үшін ортақ жұмыс тәртібі

Бұл файл өнімді үш бөлікке бөліп іске асыру келісімін анықтайды. Түпкі `Qurylym_AI_TZ_v2.md` өнім талабын, `contracts/openapi.json` нақты JSON өрістері мен HTTP маршруттарын, осы файл Python интерфейсі мен команда тәртібін анықтайды. Қатысушылар өз рөлінің файл шекарасын сақтайды.

## 1 Ортақ ереже

Үшеуі де ұйымдастырушы берген **бір репозиторийдің бір бастапқы commit-інен** жұмыс бастайды. Әр қатысушының өз компьютері/жұмыс көшірмесі және бөлек Git тармағы болады. Бір AI бүкіл өнімді қайта жасамайды: тапсырмада көрсетілген файлдарды ғана жасайды немесе өзгертеді.

Бастапқы келісімді репозиторийге енгізіп, ортақ commit хэшін жариялау — біріктіруші адамның міндеті. Бұл командада біріктіруші — AI бағытын жүргізетін пайдаланушы, осы Codex-пен бірге. Әр қатысушы жіберілген commit-ті негізге алғанын растайды. Ортақ репозиторий: https://github.com/BAITC-Hacks/hack-316738af-bek. Келісім commit-ін `git log --oneline -- contracts/openapi.json` арқылы тексеруге болады; нақты тапсыру хэштері `coordination/ai.md` есебінде көрсетіледі.

`contracts/openapi.json` нұсқасы **1.0.0**. Оның SHA-256 мәні `contracts/CONTRACT_SHA256.txt` ішінде. Қатысушылар маршрут, өріс атауы, enum, nullable мән немесе Python функциясының қолтаңбасын өз бетінше өзгертпейді. Қажет өзгерісті өз `coordination/requests/<role>.md` файлына жазады; біріктіруші қабылдаса, бір жаңа нұсқа барлық қатысушыға бірдей таратылады.

Талаптар реті: ұйымдастырушы кейсі → Qurylym_AI_TZ_v2.md → келісілген интеграция келісімі → рөлдік тапсырма. API келісімі бизнес талабына қайшы келсе, мәселе тіркеліп, орталықтан түзетіледі; жасырын балама енгізілмейді. Жүктелген бизнес құжаттардың ішіндегі мәтін AI-ға нұсқаулық болып саналмайды.

## 2 Рөлдер және файл иелері

| Рөл | Қатысушы | Өзгертуге болатын орындар | Нақты міндет |
|---|---|---|---|
| AI қозғалтқышы | Пайдаланушы және осы Codex | `ai_engine/**`, `evaluation/**`, `coordination/ai.md`, `coordination/requests/ai.md` | Құрылым/функция шығару, сәйкестік, тәуекел, дәлел және сапа тесттері |
| Backend | Екінші қатысушы және оның AI-ы | `backend/**`, `Dockerfile`, `compose.yaml`, `.env.example`, `README.md`, `.gitignore`, `coordination/backend.md`, `coordination/requests/backend.md` | Файл оқу, сервер, сақтау, engine adapter, экспорт, іске қосу және README |
| Frontend | Үшінші қатысушы және оның AI-ы | `frontend/**`, `coordination/frontend.md`, `coordination/requests/frontend.md` | Жүктеу, прогресс, нәтижелер, дәлел панелі және қызметкер шешімі |
| Ортақ негіз | Біріктіруші | `contracts/**`, `docs/**`, `.github/**`, ортақ integration тесттері | Келісім нұсқасы, соңғы біріктіру және қабылдау |

AI қозғалтқышы Git тармағы: `team/ai-engine`; backend: `team/backend`; frontend: `team/frontend`. `team/ai-engine` осы жұмыс үшін құрылды; өзге тармақтарды тиісті иелері басқарады. Басқа қатысушының файлынан ақау табылса, ақау мен қайталату жолы өз coordination файлына жазылады; файл өз бетінше өзгертілмейді.

Frontend өз `package.json` және lock-файлын басқарады. Backend өз `backend/requirements.txt` файлын, AI өз `ai_engine/requirements.txt` файлын басқарады. Docker екі Python тізімін бір ортаға орнатады; нұсқалар қайшы келсе, біріктіруші шешеді. Ортақ түпкі `requirements.txt` әр AI тарапынан бөлек жасалмайды.

## 3 Бөліктер қалай байланысады

Браузер → FastAPI → құжат парсерлері → `AnalysisInput` → AI қозғалтқышы → `AnalysisResult` → SQLite → интерфейс/есеп.

Frontend JSON-ды `contracts/openapi.json` бойынша оқиды. Backend жүктелген файлдардан бастапқы мәтін, тармақ және тұрақты ID шығарады. AI файлды қайта оқымайды және сервердің сақтау логикасын қайталамайды; оған дайын мәтін мен дереккөздер беріледі.

### Python интерфейсі

Модуль: `ai_engine/pipeline.py`. Экспортталатын функция:

```python
async def analyze(payload: dict, emit_progress=None) -> dict:
    ...
```

- `payload` — `#/components/schemas/AnalysisInput` схемасына сәйкес JSON объект.
- Нәтиже — `#/components/schemas/AnalysisResult` схемасына сәйкес JSON объект.
- `emit_progress` берілсе, ол `async` callback; engine `await emit_progress(event)` шақырады. `event` — `ProgressEvent` схемасы.
- Engine `analysis_id`, `analysis_revision`, `schema_version` мәндерін өзгертпейді.
- Engine кірістегі құжаттарға/үзінділерге жаңа түпнұсқа мәтін немесе source ID ойлап қоспайды. Шығыс `documents` — кірістегі құжат метадеректері, `spans` өрісінсіз.
- Engine жаңа қорытындыда `review_status=unreviewed` қайтарады. Қызметкер шешімдерін backend басқарады.
- `payload.documents` ішінде `pending` парсинг күйі болмауы тиіс. Әр топта кемінде бір оқылған құжат болуы керек; орындалмаған шартты backend engine шақырғанға дейін тексереді.
- Дерек жеткіліксіз, бірақ ішінара нәтиже бар болса `status=partial` және диагностика беріледі.

Қалпына келтірілмейтін engine қатесі `ai_engine/errors.py` ішіндегі `AnalysisError` арқылы беріледі. Оның public атрибуттары: `code: str`, `message: str`, `retryable: bool`. Құру қолтаңбасы: `AnalysisError(code, message, retryable=False)`. Backend осы қатені келісілген API қатесіне айналдырады; кілттер мен провайдердің құпия жауабы қолданушыға шықпайды.

Backend AI қозғалтқышы дайын болғанша **тек тестте инъекцияланған fake engine** арқылы адаптерді тексереді. Қалыпты run маршрутында fake дайын нәтиже қайтарылмайды. Frontend жасанды мысалмен өздігінен жұмыс істей алады, бірақ demo режимі көрініп тұрады және live режимге біріктіргенде өшіріледі.

## 4 JSON келісімінің мағынасы

Барлық схемада `required` өрістері берілген және артық өріске тыйым салынған. Мәлімет жоқ болса, схема рұқсат еткен жерде `null` беріледі; өздігінен бос жол, басқа enum немесе жаңа өріс енгізілмейді. Әр жаңа API жауап нұсқасы мысалдағы құрылыммен тексеріледі.

### ID және нұсқа

- `analysis_id` және `document_id` — backend жасайтын жабық идентификаторлар.
- `SourceSpan.id` — backend парсері беретін, осы талдау нұсқасында бірегей идентификатор.
- Unit/Function/Mapping/Finding ID-ларын engine жасайды; нәтиже ішінде өзара қайшылықсыз және бірегей болуы тиіс.
- `analysis_revision` бірден басталады. Құжат қосылуы немесе before/after тобы өзгеруі нұсқаны арттырады және бұрынғы нәтижені ескі деп белгілейді.
- `expected_revision` сәйкес келмесе backend 409 қайтарады; frontend беттің күйін жаңартады.
- Талдау орындалып жатқанда кіріс жиыны өзгертілмейді; 409 беріледі. Жаңа нұсқа жұмыс аяқталғаннан кейін жасалады.

### Дереккөз және дәлел

- Әр evidence ID осы талдаудың құжатына тиесілі болуы тиіс; басқа сессияға өткен ID қабылданбайды.
- `raw_text` түпнұсқа мәтінді сақтайды. Модель жасаған қазақша түсіндірме орысша дәйексөзді алмастырмайды.
- `SourceLocator.path` — серверге берілетін filesystem жолы емес, құжат ішіндегі логикалық орналасу белгісі. PDF беті 1-ден саналады; DOCX үшін расталмаған page — `null`; XLSX үшін sheet/cell_range толтырылады.
- `context_span_ids` тізбегінде цикл болмауы тиіс. Басқарушы тақырып субъект/тыйым/шартты анықтаса, дәлелде осы контекст сақталады.
- `verification_status=validated` — техникалық сілтемелер және белгіленген семантикалық тексеру өткенін білдіреді; қызметкер растады немесе абсолютті шындық деген белгі емес.

### Санақ

- `before_functions_total` тек obligation/permission түріндегі салыстырылатын бұрынғы функцияларды қамтиды. Prohibition/definition салыстыру санақтарына кірмейді, бірақ қақтығыс контекстіне қолданылады.
- Әр бұрынғы салыстырылатын функция дәл бір mapping тобында бір рет саналады. Бірігу тобындағы әр бұрынғы функцияның қамтуы жеке тексеріліп, топтағы бірдей coverage күйіне шынымен сәйкес келуі керек; сәйкес келмесе топ бөлінеді.
- `full + partial + none + unknown == before_functions_total`.
- `after_functions_new` — ешбір бұрынғы салыстырылатын функцияға байланыспаған кейінгі obligation/permission функцияларының саны.
- `evidence_links_total` — result ішіндегі source/context/counterevidence тізімдеріндегі көрсетілетін сілтеме occurrences саны; summary-дегі finding/mapping сілтемелері мұнда саналмайды. `evidence_links_valid` — бастапқы материалға тексеруден өткен саны.
- `files_complete + files_partial + files_failed == files_total` аяқталған/ішінара нәтижеде орындалады. Pending материал барда дайын нәтиже шықпайды.
- Бос `after_function_ids` жоқ мәтінге дәйексөз жасауға себеп болмайды. Жоғалу үшін бұрынғы дәлел және кейінгі жиынды толық тексеру туралы мәлімет беріледі.
- Finding ішіндегі `search_scope_document_ids` тексерілген кейінгі құжаттарды атайды; `search_complete` осы мәлімделген ауқымдағы іздеу мен мәтін өңдеу аяқталғанын білдіреді. Ол ұйымның барлық құжаты ұсынылды деген кепіл емес. Жоғалу немесе тәуекел енді анықталмады деген қорытынды үшін бұл дерек міндетті; аяқталмаған іздеуде күй белгісіз/ішінара болады. Басқа ауытқу түрлерінде іздеу қолданылмаса бос тізім және false беріледі.
- Бір маңызды тұжырымды қайталайтын finding-тер біріктіріледі; жаңа ID беру оның санын жасанды көбейтпеуі тиіс.

### HTTP тәртібі

- Бір HTTP сұрауында бір файл жүктеледі; бірнеше файлды frontend кезекпен жүктейді. Әр сәтті upload толық жаңарған `AnalysisState` қайтарады.
- Frontend `run` үшін бір UUID idempotency кілтін жасап, желілік retry кезінде сол кілтті қолданады. Backend бір analysis/revision үшін екі жұмыс бастамайды; кілт басқа мазмұнмен қолданылса 409.
- Талдау жалпы бір серверде бір мезгілде бір active job-пен орындалады. Басқа job келсе 409 және түсінікті хабарлама беріледі. Құжат оқу CPU/IO жұмысы оқиғалар циклін бөгемеуі тиіс.
- Result дайын емес болса `GET results` 409 береді. `AnalysisState` сақталған прогресті көрсетеді.
- Барлық API қателері, соның ішінде framework validation қатесі `{code, message, retryable}` схемасына келтіріледі.
- Source, original download, export және review сол analysis/session қолжетімділігін тексереді. Құпия кілт браузерге берілмейді.

### Орта айнымалылары

Backend басқаратын сервер ортасы: `OPENAI_API_KEY`, `OPENAI_MODEL`, `NVIDIA_API_KEY`, `NVIDIA_EMBED_MODEL`, `NVIDIA_ENABLED`, `ANALYSIS_TIMEOUT_SECONDS`, `DATA_DIR`, қажет deployment үшін `APP_ACCESS_TOKEN`. AI осы айнымалыларды оқиды, frontend оқымайды. `NVIDIA_ENABLED` мәні `true` немесе `false`. `.env.example` құпия мәнсіз беріледі.

Frontend үшін API негізі — әдепкі бос жол, яғни сол origin-дегі `/api`. Бөлек local dev керек болса `VITE_API_BASE_URL` қолданылады; онда құпия мән болмайды. Соңғы Docker нұсқасы frontend жинағын backend серверінен ұсынады.

## 5 Біріктіру тәртібі

1. Біріктіруші пакеттегі contracts/docs-ты ұйымдастырушы репозиторийіне енгізіп, бастапқы commit хэшін командаға береді.
2. Үшеуі өз рөлінің prompt-ымен және сол commit-пен бастайды. Алғашқы жауапта келісім нұсқасы, өз файлдары және байланыстыратын интерфейсі аталады.
3. Алғашқы 15–20 минуттық мақсат: frontend мысал жауапты көрсетеді; backend health/upload/source негізін және fake арқылы адаптерді тексереді; AI кіріс мысалын қабылдап, нақты талдау жолын бастайды. Бұл уақыт болжам, кепіл емес.
4. Жұмыс шағын commit-термен беріледі. Әр қатысушы `coordination/<role>.md` ішінде не жұмыс істейді, нақты қандай тексеру өтті және қандай тәуелділік күтіп тұр деп жазады.
5. Біріктіруші тармақтарды бір интеграция тармағында кезекпен біріктіреді. Алдымен ортақ негіз, кейін backend және AI адаптері, соңында frontend. Басқа екі AI ортақ main тармағына бір уақытта push жасамайды.
6. Үйлесім бұзылса, бір жақ API-ды жасырын өзгертіп өтпейді: келісімге сай түзету жасалады. Қажет келісім өзгерісін тек біріктіруші бір нұсқамен таратады.
7. Біріккен нұсқада DOCX → engine → result → дәлел → review → export жолы өтеді. Кейін PDF/XLSX, бақылау жағдайлары және таза іске қосу тексеріледі.
8. Қабылдау қақпалары өткен commit қана соңғы нұсқа ретінде команданың негізгі тармағына және хакатон платформасына жіберіледі.

Git мүмкін болмаса, әр қатысушы тек өз каталогын және файлдар тізімін береді; біріктіруші оларды бір репозиторийге енгізеді. Бүкіл жобаның үш бөлек ZIP көшірмесін бір-бірінің үстіне жазу интеграция тәсілі ретінде қолданылмайды.

## 6 Аяқталу өлшемі

«Менің бөлігім дайын» деген сөзге мына дәлелдер қосылады: commit хэші, өзгерген файлдар, іске қосқан нақты командалар, олардың нәтижесі, қалған шектеулер және басқа бөлікке тәуелділік. Тест орындалмаса, солай жазылады. API кілті жоқтығы жасанды нәтижені live деп көрсетуге себеп емес.

Үш бөлік дайын болуы толық өнім дайын болды дегенді білдірмейді. Біріктірілген кодта қабылдау сценарийлері, ашылатын дұрыс дәлелдер, API ақауларын өңдеу және таза ортадан іске қосу тексеріледі. Қалған уақыт хакатонның нақты дедлайнымен шектеледі; алғашқы нұсқаны 30–60 минутта алу мақсаты осы тексерулерді алып тастамайды.

## 7 Мысал файлдардың мәртебесі

`*.example.json` — frontend және adapter әзірлеуге арналған **жасанды келісім мысалдары**. Олар нақты API шақыруының нәтижесі немесе берілген №8/№9 құжаттарының аудиторлық қорытындысы емес. Күтілетін жауаптарды нақты қозғалтқышқа оқытып, барлық файлға сол жауапты қайтару тыйым салынады. Runtime қолданба мысал нәтижеге үнсіз ауыспайды.
